# Astronaut Jr — Child Usability Test Plan

## Purpose
Observe whether children in the intended age range can understand the first-use experience, start and complete a mission, interpret feedback, find progress, switch language, and resume a saved checkpoint without coaching. This is a test plan, not a report of completed sessions.

## Consent and privacy
- Obtain parent/guardian permission and have a responsible adult supervise. Explain that the website is being tested, not the child, and that participation can stop at any time.
- Do not collect names, email addresses, passwords, school names, exact locations, photos, or other identifying details. Use anonymous participant codes (P01, P02...).
- Do not create real accounts. Use guest mode or a prepared test browser profile. Do not record audio/video unless a guardian has explicitly consented.
- Use a separate browser profile so participant actions cannot overwrite anyone's real progress.

## Setup
1. Use a fresh browser profile for first-use testing.
2. Test on a phone-sized screen and a desktop/tablet-sized screen where possible.
3. Test English and Arabic, including RTL layout.
4. Observe quietly. If asked for help, say: “What would you try next?” Record the request. Do not lead the participant to an answer.

## Neutral opening script
“Thanks for helping us test this space academy. We are checking whether the website is easy to understand. You are not being tested. Please use it as you normally would and say what you are thinking. You can stop whenever you want.”

## Tasks (give one at a time)
1. **First visit:** Choose how to enter and explain where you think progress will be saved.
2. **Explore:** Find the planet explorer, open a planet file, then return to the mission path without using browser Back.
3. **Mission briefing:** Find the first available mission and explain its objective and the steps you expect to follow.
4. **Learning sequence:** Move through a lesson card, complete the activity, and answer the quiz.
5. **Feedback:** Give one incorrect quiz answer, read the feedback, and try again; then answer correctly.
6. **Progress:** Find completed missions, stars, and the next mission that can be unlocked.
7. **Resume:** Start a mission, move to a later step, close it, refresh the page, reopen it, and check the saved checkpoint.
8. **Language:** Switch Arabic/English. Check direction, button placement, scientific wording and offline availability of key labels.

## Observation fields
Record anonymous participant code, device class, language, task number, completion (yes/no), time band (under 30 sec / 30–90 sec / over 90 sec), wrong turns, help requested, exact point of confusion, participant's own words, and severity (low / medium / high). Do not infer ability or feelings from appearance.

## Success criteria
- Participant distinguishes guest play from account setup and understands progress is local-only, not cloud-synced.
- Participant finds requested sections without coaching.
- Participant identifies the mission objective and lesson → activity → quiz sequence.
- Participant understands incorrect-answer feedback and can operate dialogs with touch and keyboard.
- Participant identifies completion, stars, next unlock and resume point.
- No critical control is hidden or unusable in Arabic or English.

## Prioritisation
- **High:** blocks completion, loses progress, misleads about privacy/saving, or makes a control inaccessible. Fix before release.
- **Medium:** repeated hesitation or wrong turns, but recovery is possible. Fix in the next iteration.
- **Low:** cosmetic or preference issue without task impact. Batch for later.

## Reporting
After real sessions, report observed patterns only. State participant count and device/language coverage, separate observations from interpretations, and list the highest-impact fixes. Never fill this log with hypothetical results.
